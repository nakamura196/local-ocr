画像の文字を、手元のパソコンだけで読む道具。macOS と Windows を 1 つのコードベースから出す。

## 位置づけ

[tei-scanner](https://github.com/nakamura196/tei-scanner)（Swift / macOS 専用 / Apple Vision のみ）の後継。
変えるのは 3 点。

1. **Windows でも動く**（Flet = Python + Flutter。`~/git/kim/archival-packager` と同じ作り）
2. **読む道具を選べる**（Apple Vision だけでなく、くずし字・漢籍も読める）
3. **入口と出口を増やす**（IIIF マニフェスト入力、TEI/XML 出力）

## 何をする道具か

**画像 → 文字**に徹する。読んだ文字をコピーして、利用者が好きなところへ貼る。
校正の画面（TEI/IIIF エディタ）とは**互いを知らない**。繋ぐときはクリップボード経由にする
（エディタ側に「枠の画像をコピー」を足せば、貼り付けるだけで繋がる）。

## 読む道具（エンジン）

| id | 名前 | 対応 | 取得 | 向き |
|---|---|---|---|---|
| `apple-vision` | Apple Vision | macOS | 不要 | 現代の活字・手書き。速い |
| `windows-ocr` | Windows 標準 OCR | Windows | 不要 | 同上。`Windows.Media.Ocr` |
| `ndl-lite` | NDLOCR Lite | 両方 | 150MB | 近代資料・活字（済） |
| `ndl-koten-lite` | NDL古典籍OCR Lite | 両方 | 79MB | 古典籍・くずし字（済） |
| `paddle-vl` | PaddleOCR-VL | 両方 | 約 1.8GB | 漢籍・多言語・版面解析 |
| `tibetan` | BDRC Yigdzin 1 | 両方 | 未定 | チベット語（**保留**） |

### 渡すのは「ページ」か「1 行」か

**`recognize` は「これは既に 1 行に切ってある」を受け取れるようにする。**
校正の流れ（エディタで枠を直して、その枠だけ読み直す）では、渡ってくるのは 1 行なので、
そこにレイアウト検出をかけると無駄なうえに切り直されて崩れる。

| 読む道具 | 効くか |
|---|---|
| NDL 2 種 | **効く。** レイアウト検出 → 文字認識の 2 段。検出を飛ばして認識だけ呼ぶ |
| Tesseract | **効く。** `--psm 7`（1 行として読む） |
| PaddleOCR-VL | 効かない。渡した画像をそのまま読む（ページ全体なら「Spotting:」で行を見つけさせられる） |
| Apple Vision / Windows 標準 | 選べない。OS の中で完結している |

**枠ごとに渡すほうが、速さ以外のすべての点で有利。** 全体を渡すと長辺 1600px に縮むので
1 文字が潰れる（実寸 430×6205px の行なら、ページ全体で 67px、その行だけなら 132px。**約 2 倍**）。
実測でも 1 行ずつで CER 2.34%（NDL古典籍OCR は 4.18%）。**測り方**は、東洋文庫蔵
『酉蓮社』の人手による翻刻 352 行を正解として、同じ画像を 2 通りの渡し方で読ませ、
行ごとに突き合わせたもの。正解のデータは別の（公開していない）作業のもので、
このリポジトリには入っていない。全体を「OCR:」で渡すと枠を返さず、多段組では順番も狂う
（「Spotting:」なら行ごとの位置が返る。下の「窓口の口」）。

**共通の口は `engines/base.py` の `Engine`。** 足すときは `engines/__init__.py` の一覧に 1 行足すだけ。
取得・キャッシュ・進捗・失敗時の文面は共通側が持ち、エンジンには書かない。

### 各エンジンの実装メモ

- **Apple Vision**: pyobjc (`Vision` / `Quartz`)。`VNRecognizeTextRequest`。
  枠は左下原点の 0..1 で返るので、画素座標・左上原点に直す。**初回の呼び出しだけ約 15 秒**（以後 0.1 秒）
- **Windows 標準 OCR**: `winrt-Windows.Media.Ocr` ほか。日本語は言語パックが要る
- **NDL 2 種**（済）: 上流は [ndl-lab/ndlocr-lite](https://github.com/ndl-lab/ndlocr-lite) と
  [ndl-lab/ndlkotenocr-lite](https://github.com/ndl-lab/ndlkotenocr-lite)。**どちらも CC BY 4.0**（表示が要る → `NOTICE`）。
  ONNX Runtime で動く。構成は レイアウト検出（DEIMv2 / RTMDet）→ 文字認識（PARSeq）→ 読み順。
  中身は `local_ocr/ndl/`、モデルの取得先は `core/ndl_assets.py`。**上流の repo の動かない番号（コミット）で
  指している**ので、上流が差し替えても手元の結果は変わらない。上げるときは番号と、
  組で使う文字の一覧（`ndl/charset/`）を一緒に取り直す。
  - **依存を 4 つ増やさずに済ませた**（OpenCV / lxml / PyYAML / networkx）。理由は `ndl/__init__.py`。
    足したのは `onnxruntime` と `numpy` だけ
  - **上流と結果が変わるところが 2 つある。どちらも上流の書き落としで、こちらが正しい。**
    直す前に `ndl/recognize.py` と `ndl/order.py` のその場のコメントを読むこと。
    上流の試し画像 10 枚で突き合わせた結果も、そこに書いてある
  - 速さの目安（M 系 Mac・2000px 前後の 1 枚）: 古典籍 0.2〜0.3 秒、近代資料 0.4〜0.7 秒。
    モデルを開くのに初回だけ 3〜6 秒
- **PaddleOCR-VL**: llama.cpp（`b10776`）の GGUF。常駐の `llama-server` を内側で立て、
  OpenAI 互換の窓口に投げる。**サーバの存在は利用者に見せない**。
  **版面まるごと渡すと、枠を返さないうえ、多段組（偈頌）では帯に割って順番が狂う**
  （エディタ側 `tei-iiif-editor/apps/editor/lib/ocr/engines/paddle-local.ts` の冒頭に実測の記録がある。
  単純な 1 ブロックの頁なら通るが、一般化してはいけない）。
  枠のある校正の流れでは、枠ごとに切って渡すのが正しい
- **チベット語**: BDRC「Yigdzin 1」（Apache-2.0）は **PaddleOCR-VL-1.6 の派生**なので同じ道に乗る見込み。
  ただし配布は safetensors のみで **GGUF が無い**。変換の実験が要るため v1 では見送る

## 入口

- 画像ファイルを選ぶ
- **クリップボードから貼り付ける** ← エディタとの連携はここ
- フォルダ（複数ページの一括処理）
- **IIIF マニフェストの URL** ← 各カンバスの画像を順に読む

**渡されたものをページの並びに開くのは `core/source.py` だけ。** 画面も端末も
ここを通す。2 か所に書くと、フォルダの並び順やマニフェストの読み方が割れて、
出てくる TEI が食い違う。返すのは `Bundle`（題・出どころ・`Item` の並び）で、
`Item` は「まだ開いていない 1 ページ」（手元のファイルか、取り寄せ先の URL）。

- **版面は読む直前に 1 枚ずつ開く。** 何百ページを一度に開くと机に載らない。
  見ていないページの版面は手放す（`Doc.keep_only`）。読んだ文字・枠・**版面の寸法**は
  残すので、TEI は版面を手放したあとでも書ける
- **フォルダは人が見て自然な順に並べる。** ただの文字の順だと `10.jpg` が
  `2.jpg` より前に来る。中のフォルダまでは潜らない

### IIIF（`core/iiif.py`）

- **v2 と v3 の両方を読む。** 公開されているものは今も 2 系が多い。欲しいのは
  「カンバスの並び」と「その版面の URL」だけなので、取り出し方を 2 通り書いて後ろは一つにする
- **画像サービスがあれば縮めて貰う**（長辺 1600px に収まる幅）。頼み方は `{幅},`
  ―― Image API 2 でも 3 でも通る。`!w,h` は通らない配信元がある。サービスが無い
  マニフェストでは、貼られている画像をそのまま貰う
- **取り寄せた版面は手元に残す**（`data_dir()/iiif`）。ページを行き来するたびに
  貰い直さない。設定画面に大きさを出し、そこから消せる
- **`<graphic>` は IIIF の URL をそのまま指す。** 手元の道と違い、渡した先でも開ける
- **失敗は鍵で投げる**（`ManifestError`）。core は画面の言語を知らないので、
  文面は `ui/i18n.py` が付ける。画面では「窓を閉じずにその場で」出す（打ち直せるように）
- **「画像はこのパソコンから出ません」は嘘にしない。** IIIF は*取り寄せ*なので、
  入力の窓に「マニフェストと版面は配信元から取り寄せます。読むのはこのパソコンの中だけです」と添える

### 束（複数ページ）の画面

`Doc`（題・`Job` の並び・いま何ページ目か）。**1 枚のときも長さ 1 の束**として扱う。
こうしておくと、画面の作りが「1 枚か、たくさんか」で割れない。

- 版面の下に**ページの帯**（2 ページ以上のときだけ）。`◀ 3 / 20 ▶` ／ ページの名前 ／
  読み終えた数 ／「すべて読む」。**上帯には足さない**（狭い窓で読む・コピー・保存が押し出される）
- **黙って全部を読み始めない。** 束を開いた直後は 1 ページ目を出すだけ。
  何百ページの取り寄せと読み取りは、押してから始まる
- **途中で止められる。** 読んでいる間、ボタンは「中止」になる。押した 1 ページは最後まで読む
- 下ごしらえ（重みの読み込み）は**束で 1 回だけ**。ページごとにやり直さない
- 読み終えたページは版面を手放す。**見ているページが読み終わったら、その場で出す**（待たせない）
- 「すべて読む」は、**まだその道具で読んでいないページだけ**を読む。
  全部読み終わっているときは、もう一度ぜんぶ読む（読み直しの手立て）
- 保存は「このページ」と「すべてのページ」。**書き出すのは読み終えたページだけ**
  （読んでいないページを空で並べると、「読んだが何も無かった」ページと見分けが付かない）

## 出口

- 文字をコピー
- **テキストで保存**（`.txt`）
- **TEI/XML**（`.xml`）。tei-scanner と同じ形にする:
  1 ページ = 1 `<surface>` + `<graphic>`、1 行 = 1 `<zone>` と `<lb corresp="#…">`
  （枠を返さないエンジン（PaddleOCR-VL の版面読み）では `<zone>` を省く）

組み立ては `core/tei.py`、ファイルに書くのは `core/export.py`。決めごとは 4 つ。

- 保存するのは **いま版面に出ている結果**（`Job.primary`）。「くらべる」で
  「これを使う」を押したものが対象になる。コピーと同じ決まりにしてある
- **「まとめて」で直した文字が、行の一覧にも TEI にも効く。** 行数を変えなければ、
  エンジンが返した枠をそのまま連れていく（`ui/state.py` の `Run.lines`）
- **`<graphic>` は TEI から見た相対の道で書く。** 絶対の道を書くと、そのパソコンで
  しか開けない TEI になる。版面が遠い（`../..` より上）か、貼り付けた画像で元の
  ファイルが無いときは、**版面を TEI の隣に置いて**それを指す（元のファイルが
  あるなら詰め直さずに写す。JPEG を PNG に開き直すと 0.8MB が 4.5MB になる）
- 保存先は毎回ダイアログで選ぶ。**開く場所だけ前回の続き**にする（`save_dir`）。
  **束（フォルダ・IIIF）を入れても、出力先を固定する設定は作らなかった。**
  束は「1 ファイル（N ページの TEI）」に書き出す作りなので、書く回数は 1 枚のときと変わらない。
  既定のファイル名を束の題にして、ダイアログの手間だけを減らしている
  （ページごとにばらして書くようになったら、そのとき考える）
- 束の `<graphic>`: 取り寄せたページ（IIIF）は**その URL**、手元のファイルは相対の道。
  相対にできないときは、**1 枚なら隣に写し、束なら写さずそのままの道を書く**
  （何百枚も増やさない。端末から使ったときと同じ決まり）

## ほかの道具から使わせる

**この機械の「OCR 置き場」にする。** 特定の相手（TEI/IIIF エディタ）に合わせた作りにしない。
繋ぎたい相手は今後も増えるので、合わせるのは相手ではなく**口の形**。

出し方は 2 つ。境目は「ブラウザの中かどうか」。

| 相手 | 使わせ方 |
|---|---|
| 手元の別のプログラム・スクリプト | **CLI**（済）。窓口は要らない |
| ブラウザの中で動く頁 | **窓口（HTTP）**。ブラウザは外のコマンドを起動できない |

### 開け閉め（済。設定画面の「ほかの道具から使えるようにする」）

**開けている間だけ、窓口（`core/gateway.py`）を立てる。** 出すのは 2 つ、
**接続先**（`http://127.0.0.1:8080`）と、**繋いでよい相手**の一覧。
どちらも隠すと、繋がらないときに何を直せばよいか分からなくなる。
開け閉めは `core/bridge.py`、画面は `ui/settings.py` の `BridgeCard`。

- **既定は閉じている。** 開けた時点で、その機械で開いているどの頁からでも
  画像を投げられる状態になる。設定画面で利用者が開けたときだけ開く
- **繋いでよい相手は窓口が見る**（`bridge.allows`）。閉じている間と、一覧が空のときは
  誰も通さない。一覧は呼ばれるたびに読むので、**相手を変えても立て直さなくてよい**
  （2026-09-25 まで：llama-server を 8080 にそのまま出し、`--cors-origins` で絞っていた。
  llama-server は起動のときの一覧しか見ないので、相手を変えるたびに 1 分かけて立て直していた）
- **llama-server は窓口の後ろ（8082）に隠し、誰も通さない。** `--cors-origins` には
  誰も名乗れない相手（`https://none.invalid`。`.invalid` は RFC 2606 で予約）を渡す。
  **省かない。** llama-server の既定は `*` で、省くと頁から直接読めてしまう
- **Host が 127.0.0.1 / localhost でない呼び出しは断る。** よその名前を 127.0.0.1 に
  向け直して頁と同じ出どころに見せかける手口（DNS リバインディング）への備え
- Origin の無い呼び出し（同じ機械の端末・スクリプト）は通す。ブラウザは POST には必ず
  Origin を付けるので、頁から読ませる呼び出しは一覧で絞れる
- **開けたままにしてあれば、次の起動で開け直す**（`app.py`）。前回の終了でサーバは
  止まっている。開いているつもりで繋がらない状態を作らない
- **開けるのに失敗しても、設定は倒さない。** 「開けるつもりだが開けていない」と
  次にすることを設定画面に出す。黙って閉じると、なぜ繋がらないか分からない
- PaddleOCR-VL を削除しても、窓口は閉じない。ほかの道具は使い続けられ、消した道具を
  頼まれたときは「取得していません」（409）と返す
- 待つのは 127.0.0.1 だけなので、同じ機械の中からしか繋がらない
- https の頁から 127.0.0.1 を呼ぶと、Chrome の「ローカルネットワークへの接続を許可」が
  最初の 1 回出る。これは消せない

### 窓口の口（済。2026-09-25）

```
GET  http://127.0.0.1:8080/v1/engines   → {engines:[{id, label, ready, lines}]}
POST http://127.0.0.1:8080/v1/ocr       → {engine, image, lines} を渡すと
                                           {engine, width, height, seconds, text,
                                            lines:[{text, box:{x,y,w,h}, polygon:[[x,y]×4]}]}
GET  http://127.0.0.1:8080/health                  ┐ 前からある口。PaddleOCR-VL の
POST http://127.0.0.1:8080/v1/chat/completions     ┘ llama-server へそのまま渡す
```

- 中身は `engines/base.py` の `recognize(画像) → Result` を**そのまま外に出すだけ**。
  **この機械の「OCR 置き場」にする**ので、特定の相手に合わせない。使えるのは、
  この OS で動いて取得済みの道具すべて（Apple Vision・NDL 2 種・PaddleOCR-VL・Yigdzin）
- `engine` を省くと PaddleOCR-VL。`image` は `data:` の URL でも base64 だけでもよい。
  `lines` は既定で真。偽にすると文字だけ（PaddleOCR-VL は「OCR:」で読む）
- 座標は、渡された画像の画素。**取得はよそからの呼び出しで始めない**（409 `not_fetched`）
- 読みが崩れて打ち切ったとき（定規など、下記）は 422 `runaway`。呼び手は「範囲を切って読み直して」と案内する
- 下の 2 つは互換のため。TEI/IIIF エディタは今この 2 つで話しているので、エディタを
  直さなくても動き続ける。以前の起動スクリプト（zip）も同じ 8080 に同じ 2 つを立てる

**PaddleOCR-VL の行の位置は「Spotting:」で取る**（`core/ocr.py` の `spot`）。
PaddleOCR-VL 1.5 以降は、指示を「OCR:」ではなく「Spotting:」にすると、行ごとに
`本文<|LOC_x1|><|LOC_y1|>…<|LOC_y4|>`（4 隅、画像の幅・高さを 0〜999 に割った目盛り）を返す。
**llama-server の `/v1/chat/completions` はこの `<|LOC_n|>` を消す。** 本文だけが返るので、
位置が無いように見える（2026-09-25 まで「PaddleOCR-VL は枠を返さない」と誤解していた）。
そこで `/apply-template` で会話を文字列にし、`/completion` に `return_tokens` を付けて
少しずつ受け取る。本文は `content` から、位置は印の番号から拾う（漢字 1 字が複数のトークンに
割れると、字がそろった回にトークンが最後の 1 つしか載らないため）。
酉蓮社 117-10 の見開きで 14 行・3〜7 秒、枠は列にぴったり合った。くせ：題の列に朱印を混ぜる。

**定規が写っていると崩れる。** 右端から読み始めるので、右に定規があると「1, 2, 3, …」と
数え続け、出力の上限まで本文に届かない（酉蓮社 030_01_025 で 1,041 行・枠 0）。
公式の PaddleOCR-VL は読む前に版面の区分け（PP-DocLayout）を通すが、ここでは読むモデルしか
動かしていない。そこで 2 段で防ぐ。

1. 読む前に定規を背景の色で塗る（`core/ruler.py`）。背景の帯で本と離れ、端から端まで通り、
   目盛りが一定間隔で並ぶ細い帯を探す。目盛りの強さは定規 0.15〜0.25、本文の列・柱・
   表紙の縁・本の小口は 0.02〜0.06 で、ここで分かれる。1 枚 0.02〜0.04 秒。
   030_01_025 は 134 行すべて枠つき・25 秒になった
2. それでも位置の付かない行が 20 行続いたら接続を切り、`Runaway`（窓口は 422）。
   本と接して写った定規はこちらで止まる（塗らずに読ませた実測で 3.5 秒。以前は上限まで 40 秒）

**TEI/IIIF エディタとの接続は、この窓口の最初の利用者という位置付け。**
いまは枠ごとの読み直し（前からある 2 つの口）だけ。「ページ全体の OCR」（枠をまとめて作る）
を PaddleOCR-VL でも行うには、エディタから `/v1/ocr` を呼ぶよう直す（未着手）。

## 端末から使う（CLI）

画面を開かずに、同じ道具で同じ結果を出す口。`src/local_ocr/cli.py`。

```
local-ocr 画像.jpg                                   # 文字を標準出力へ
local-ocr フォルダ --format tei --out out.xml        # 中の画像をまとめて 1 つの TEI に
local-ocr https://…/manifest.json --format tei --out out.xml   # 全カンバスを 1 つの TEI に
local-ocr --list-engines                             # 読む道具と、取得の要否
```

- **flet を取り込まない。** 画面の無いところ(他のスクリプトの中・CI)でも動かせるように、
  `engines/` と `core/` だけを使う。画面で保存したものと中身が一致する
- **渡されたものの開き方は画面と同じ**（`core/source.py`）。フォルダは中の画像を
  人が見て自然な順に、`http(s)://…` は IIIF マニフェストのカンバスに開く。複数ページの TEI は
  `<surface>` が並ぶだけなので、組み立てはそのまま使える（`core/tei.py` は元々 N ページを取る）
- TEI の題は `--title` > 束の題（フォルダ名・マニフェストの題）の順
- **読んだ中身は標準出力、進みぐあいと失敗は標準エラー。** 混ぜるとパイプで渡せない
- 取得の要る道具は、`--fetch` を付けないと落とし始めない（画面側と同じ決まり）
- 画像を勝手に写さない。`<graphic>` は書き出し先から見た相対の道。相対にできないときだけ絶対の道。
  取り寄せたページ（IIIF）は、その URL をそのまま指す

## 画面

**市販のアプリと同じ水準に仕上げる。** 道具として毎日開かれるものなので、
「動くが素っ気ない」では使われない。

### 起動画面（ランディング）

起動直後はいきなり作業画面にせず、**受け皿の画面**を出す。

- アプリ名と、1 行の説明（「画像の文字を、このパソコンの中で読みます」）
- 画面の大半を占める**投入エリア**。「画像を選ぶ」「貼り付け」「フォルダ」
  「IIIF マニフェスト」を並べ、枠の中はどこを押しても画像を選べる
  （**ドラッグ＆ドロップは Flet 0.86.2 では作れない**。2026-09-20 に手元の 0.86.2 を
  調べ直して確認した: `ft.DragTarget` はアプリの中の `ft.Draggable` しか受け取らず
  (`DragTargetEvent.src` の型が `Draggable`)、OS からのファイル投下を知らせる
  イベントはどこにも無い。Flet 側に口ができたらここに足す。
  それまでの代わりは 複数選択 / フォルダ / 貼り付け / 端末から使う)
- **「画像はこのパソコンから出ません」を目に入る場所に置く。**
  手元で動くことがこの道具の価値なので、隠さない
- 読む道具（エンジン）は控えめに。既定は**取得の要らないもの**（macOS なら Apple Vision）にして、
  何も準備せずに 1 回目が成功するようにする
- 前回開いたものがあれば、その続きから戻れるようにする

### 作業画面

左右 2 面。左に版面（枠の重ね描きつき）、右に読んだ行。
行を選ぶと対応する枠が光る（tei-scanner と同じ操作感）。
上部に エンジン / 実行 / コピー / 保存（テキスト・TEI/XML）。

- **1 つで読んだときは、いま読んだ道具の結果を版面に出す**（`Job.record(..., prefer=True)`）。
  2026-09-20、ここが抜けていて「道具を変えて読み直しても前の道具の結果が出たまま」になり、
  読めている道具が読めていないように見えていた。くらべるときだけは、先に読み終えたものを
  出したままにする（あとから勝手に入れ替わらないように）
- 「まとめて」は読みながら直す場所。行の一覧より**文字を大きく、行間と余白を広く**取る
  （`content_padding` を内側に入れる。外の入れ物だけだと折り返しが縁に触れる）
- 枠の線の太さは**画面の点で決まる**ので、元画像の画素数では変わらない。
  大きく引き伸ばしているとき（小さな切り抜き）だけ、縮尺に合わせて少し太くする（`_stroke`）

### くらべる

作業画面の上部で「くらべる」に切り替えると、**同じ画像を複数のエンジンで読み、
結果を横に並べる**。列ごとに 行数 / 文字数 / かかった秒数 を出す。
どれを版面に重ねるかは利用者が選ぶ（「これを使う」）。コピーと保存は、選んでいるものが対象。

- **道具は待ち合わせない。** 並行して動かし、終わったものから列に出す
- 秒数は**読んだ時間だけ**。下ごしらえ（サーバの起動・重みの読み込み）は
  「（準備 41 秒）」と分けて出す。混ぜると 1 回目と 2 回目で桁が変わり、
  道具どうしの速さがくらべられない
- 未取得の道具は列に「まだ取得していません」と出すだけで、**黙って落とし始めない**

### 設定画面

読む道具の一覧。それぞれ「取得済み / 未取得（◯◯MB）」を出し、その場で取得・削除できる。
1.8GB のものがあるので、**何をいつ落とすかを利用者が決められる**ようにする。

「ほかの道具から使えるようにする」もここに置く（上の「ほかの道具から使わせる」）。
開けている間だけ接続先と、繋いでよい相手の一覧を出す。**閉じている間は何も出さない** —
閉じているのに接続先が見えていると、繋がると思って試すことになる。

### 画面の置き場所

`ui/` の下に 1 画面 1 ファイル（`landing.py` / `work.py` / `settings.py`）。
`app.py` は「どれを出すか」と画面をまたぐ操作（画像を渡す・コピー・キーボード）だけを持つ。
画面どうしは互いを知らない。共有するものは `ui/state.py`（いま読んでいる画像と結果）、
`ui/status.py`（下の 4 状態）、`ui/theme.py`（色と余白）、`ui/i18n.py`（文言）。

### 状態の見せ方

空・読み込み中・取得中・失敗の 4 つを、どの画面でも同じ形で出す。
失敗は**何をすればよいかまで**書く（「起動していません」で終わらせない）。

### 仕上げ

- アプリのアイコン（配布物・Dock・ストア掲載で要る）
- 日本語 / 英語の切り替え（済。文言は `ui/i18n.py` に全部集めてある。設定画面で切り替える）
- 明るい / 暗いテーマの両方で破綻しないこと（済。設定画面で選べる）
- キーボード: ⌘V で貼り付け、⌘C でコピー、⌘O で開く

## 踏んだ落とし穴（Flet 0.86）

古い版の書き方がそこら中の記事に残っているので、**必ず手元で確かめてから使う**。

- `ft.app()` は非推奨。`ft.run()`
- ボタンのラベルは `text` ではなく `content`
- `ft.ImageFit` は無い。`ft.BoxFit`
- `ft.dropdown.Option` ではなく `ft.DropdownOption`。変更の通知は `on_change` ではなく **`on_select`**
- `FilePicker` は overlay ではなく **`page.services`** に足す。`on_result` は無く、
  **`await picker.pick_files(...)` が選ばれたものを返す**（ハンドラを `async def` にする）
- クリップボードは `page.clipboard.set/get/get_image/set_image`。**すべて await が要る**
- `ft.Image` は `src` が必須。空文字で置くくらいなら作らない
- **前の実行のウィンドウが残る。** 「Working…」のまま固まって見えるときは、たいてい古い窓を見ている。
  `pkill -f Flet.app` してから確かめる。
  **`page.window.destroy()` はコルーチン**なので、そのまま呼んでも窓は閉じない
  （2026-09-20 に確認。`RuntimeWarning: coroutine 'Window.destroy' was never awaited` が出るだけ）。
  `app.py` の窓を閉じる処理がこれ。閉じたいときは `page.run_task(page.window.destroy)`
- **自前のスレッドから `page.update()` を呼ばない。** 動くこともあるが、
  途中から画面に届かなくなる(数字だけ変わって一覧が古いまま、など)。
  重い処理は `asyncio.to_thread`、画面の書き換えは `page.run_task` の
  コルーチンの中で行う。スレッドの中から知らせたいときは `page.run_task` を使う
  (これだけはスレッドをまたいでも安全)
- **同じ部品を別の親に入れ直さない。** 画面の一部を組み替えるときは、
  その画面ごと作り直す(`go("work")`)。使い回すと、それ以降の書き換えが届かなくなる
- `ft.SegmentedButton` の `selected` は **list**。docstring には set と書いてあるが、
  set を渡すと `can not serialize 'set' object` で落ちる
- **中身の無いボタンを作らない。** `ft.FilledTonalButton(visible=False)` のように
  `content` も `icon` も無いと、`visible=False` でも更新時に弾かれる。
  後から中身を決めたいときは、空の `Container` を置いてそこに入れる
- `ft.Icon` は第 1 引数が必須で、後から変えるときの属性は `name` ではなく **`icon`**
- `FilePicker.save_file()` が返すのは **選ばれた道(パス)だけ**。書き込みはこちらで行う
  (`src_bytes` は web とスマホ用)。拡張子を付けずに閉じられることがあるので、
  こちらで揃える
- **`ft.PopupMenuButton` の中に本物のボタンを入れない。** 中のボタンが先に押されて、
  一覧が開かないことがある。押せない `Container` で見た目だけ作る(`theme.menu_button`)
- 置かれた後の実寸を教わる手立てが無いので、版面の大きさは
  `page.window.width/height` からの引き算で決めている(`work.py` の `_budget`)
